# InfraDev Academy Brand Book

> More than a visual identity.
>
> A commitment to quality, engineering and continuous learning.

---

# Purpose

This Brand Book defines the identity of InfraDev Academy.

It establishes how the Academy communicates, teaches, documents, designs and delivers value.

The objective is to ensure consistency across every product, document and interaction.

---

# Brand Positioning

InfraDev Academy is an engineering-first educational platform.

Knowledge is treated as a product.

Documentation is treated as software.

Learning is treated as an ongoing engineering process.

---

# Mission

Transform practical experience into structured knowledge capable of accelerating professional growth.

---

# Vision

Become one of the world's leading engineering-oriented educational ecosystems.

---

# Brand Personality

InfraDev Academy should always be perceived as:

✔ Professional

✔ Accessible

✔ Curious

✔ Precise

✔ Practical

✔ Trustworthy

✔ Modern

✔ Engineering-Oriented

---

# What We Believe

We believe that:

Understanding is more valuable than memorization.

Practice is more valuable than passive consumption.

Documentation is part of engineering.

Every solved problem deserves to become reusable knowledge.

Technology changes.

Concepts remain.

# Communication Style

Tone of Voice

Professional.

Friendly.

Objective.

Respectful.

Educational.

Never arrogant.

Never sensationalist.

---

# Writing Style

Use:

Short paragraphs.

Clear explanations.

Progressive learning.

Consistent terminology.

Simple language without sacrificing technical precision.

---

Avoid:

Clickbait.

Exaggerated promises.

Artificial urgency.

Unnecessary jargon.

Overcomplicated explanations.

---

# Learning Philosophy

Every content should answer:

Why?

How?

When?

Where?

What can go wrong?

How can I practice?

Where can I learn more?

---

# Educational Standards

Technical Notes (NT)

Teach concepts.

Laboratories (LAB)

Teach execution.

Case Studies (CASE)

Teach reasoning.

Guides

Teach complete processes.

References

Teach consultation.

Templates

Teach standardization.

---

# Visual Identity

The visual identity should communicate professionalism and clarity.

Prioritize:

Minimalism.

Readable typography.

Consistent spacing.

Accessible colors.

Simple diagrams.

Clean code examples.

---

# Diagrams

Whenever possible, diagrams should be created using Mermaid.

Benefits:

Version control.

Easy maintenance.

Git compatibility.

Diff-friendly.

---

# Code Examples

Code should be:

Well formatted.

Commented only when necessary.

Minimal.

Functional.

Easy to reproduce.

---

# Screenshots

Screenshots should:

Highlight the relevant area.

Hide confidential information.

Use consistent resolution.

Prefer dark mode when appropriate.

---

# Real Case Studies

Real scenarios are encouraged.

However:

Client names must be anonymized.

Sensitive data must be removed.

Company-specific intellectual property must never be disclosed.

The educational value must remain.

---

# Documentation Quality

Every document published by InfraDev Academy should be:

Technically correct.

Editorially reviewed.

Versioned.

Referenced.

Connected to related documents.

Continuously improved.

---

# Internationalization

Content should be designed for multilingual publication.

Primary languages:

English

Portuguese

Translations should preserve technical consistency.

---

# Brand Promise

Every learner should leave the Academy with more than information.

They should leave with understanding.

---

# Final Statement

InfraDev Academy exists to demonstrate that engineering excellence is built through curiosity, practice, documentation and continuous improvement.

Every document is part of that mission.
